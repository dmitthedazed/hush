# 360 Reality Audio: персонализация по ушам (Sound Connect → облако → профиль)

Дата исследования: 2026-10-21. Источник: декомпиляция Sound Connect (`com.sony.songpal.mdr`, jadx + apktool), данные приложения на телефоне (только структура), веб-поиск.

Метки уверенности: [H] высокая (прямо в коде/данных), [M] средняя (вывод из нескольких фактов), [L] низкая (гипотеза, не проверено).

## Краткий вывод

- Персонализированный HRTF строится в облаке Sony (IAC, `api.iac.meta.ndmdhs.com`). Клиент только снимает фото, отправляет данные и получает `hrtf_id` и URL бинарника профиля. [H]
- Профиль из облака можно скачать по `hrtf_id` без доступа к ушам пользователя, если есть действующий x-api-key и авторизация аккаунта. Аутентификации и API-ключ мы не трогали и не документируем. [H]
- Публичного SDK/API для сторонних разработчиков по персонализации я не нашёл. Формат бинарника HRTF не описан публично. [M]
- Системно применить чужой HRTF к звуку телефона нельзя без root и аудио-HAL-доступа. Потребители: сами приложения 360RA (Sony) и их плееры. Для Hush реалистично только собственная конволюция (бинауральный рендер) внутри Hush. [M]
- Вердикт: **NO-GO** для "взять профиль Sony и использовать в Hush как есть". **GO (умеренный объём)** для собственного бинаурального рендера с обычным (не персонализированным) HRTF. Персонализированный профиль стоит только при наличии легального доступа от Sony.

## 1. Поток (flow)

1. Захват: `com.sony.songpal.earcapture.common.EarCapture` (камера телефона, TextureView, режимы `CaptureMode`, `CapturePosition`, голосовые подсказки `EarCaptureFeedback`). Распознавание уха через OpenCV (нативные libopencv_* в `native-libs/arm64-v8a`). [H] Точные классы детекции уха в `common/*` не разбирались подробно. [M]
2. Модель уха: `com.sony.songpal.earcapture.j2objc.immersiveaudio.EarImage$EarType` = {LEFT, RIGHT}. Битмапы левого/правого уха показываются в `jp/co/sony/...` и `hq/b.java`, `iq/o0.java` (экран WS_FSM_Photograph_Ear_L/R). [H]
3. Облако, загрузка: `com.sony.songpal.earcapture.j2objc.immersiveaudio.z.e(...)` -> POST `/hrtf/upload`, тело JSON `{"data": <bytes как String>}`, заголовки `x-api-key`, `Content-Type: application/json;charset=utf-8`. Ответ содержит `download_url`. [H] Формат `data` (сырые bytes, base64 или JSON-измерения) не установлен, код использует `new String(bArr)`, то есть ожидается текст. [L]
   - Метод `z.A(byte[])` ("getHrtfOneTimeUrl") возвращает одноразовый URL загрузки. Если байтов нет, ошибка `AppInternalError: HRTF is empty.` [H]
4. Создание HRTF: `IaController.r(hrtfId, callback)` -> `IaController.g` -> `z.z(...)`/`z.g(...)`. Ожидание готовности: callback `ExecuteHrtfCreationCallback` с ProgressState (DOWNLOADED и др.). [H]
5. Получение профиля: GET `/hrtf/{id}/all` (`z.f`) и GET `/hrtf_by_hrtf_id/{id}?mode=0` (`z.g`, таймаут 3 с). Из JSON берутся поля `hrtf_url` (бинарник скачивается по HTTP) и `media_data_key`. Итог: список `earcapture.j2objc.immersiveaudio.b(bytes, mediaDataKey)`. [H]
6. Хранение: `SharedPreferences` `IaDataAccessorAndroid.xml` (ключи `SP_APP_LIST_JSON`, `SP_APP_LIST_JSON_SAVE_MILLIS`) — только кэш списка приложений, а не сам HRTF. Бинарники HRTF в prefs не найдены. [H] Realm `asc_opt_backup_data_repository.realm` и `ContextLib` тоже не проверялись по содержимому (приватные данные). [M]
7. Применение: два пути.
   a. Сторонние приложения 360RA-экосистемы: deep link `<scheme>://immersive-audio.sony.com/start-optimize?hrtf=<id>&cp=<onetime_url>&app=<...>&dev=<...>&devtype=<active_a2dp|active_a2dp_wired|passive_wired>` (`IaController.p(...)`). Запуск через `launch_type`: `adjust`, `one_link`, и др. [H]
   b. Системный путь (только 360RA app и аудио-HAL): `IaUtil.java:540` проверяет `content://jp.co.sony.threesixtyra.system.HrtfProvider/hrtf/360ra`, `IaUtil.java:542` читает `AudioManager.getParameters("360ra_hrtf_personalized")` (значение `=1`). Intent-extra `jp.co.sony.threesixtyra.settings.EXTRA_HRTFS` (`IaUtil.java:427`). [H]
8. Головные наушники: в декомпиляции Tandem/MDR (`tandemfamily`, `kmp/tandem`) не найдено команды передачи HRTF в гарнитуру. Значит, профиль на гарнитуру по протоколу MDR не грузится. Применяет телефон/приложение. [M] Прошивка гарнитуры может получать профиль иным путём (не виден в приложении). [L]

Вывод по "кто применяет": приложение/телефон (через 360RA или HAL-параметр), а не прошивка наушников, по доступным данным. [M]

## 2. Эндпоинты (без ключей и токенов)

Базовый URL (`z.w()`, класс `com.sony.songpal.earcapture.j2objc.immersiveaudio.z`) [H]:
- PROD: `https://api.iac.meta.ndmdhs.com/v1`
- demo: `https://api-demo.iac.meta.ndmdhs.com/v1`
- QA: `https://iac-api.meta.csxdev.com/v1`

Пути:
- POST `/hrtf/upload` — загрузка данных (`z.e`)
- GET `/hrtf/{hrtfId or userId}/all` — список HRTF (`z.f`, `zVar.f29744c` = id)
- GET `/hrtf_by_hrtf_id/{id}?mode=0` — бинарники по id (`z.g`)
- GET `/application/sound_ar/list/?model_name=&firmware_version=&os=&country_code=` — список SAR-приложений (`z.a`)
- GET `/music_service_provider/list/?os=&device_type=mdr` (`z.E`)
- GET `/device/list`, `/device/clearphase/{name}` (`z.d`)
- Картинки: `https://image.iac.meta.ndmdhs.com/sp/...` (icon_url) и dev-вариант `iac-image.meta.csxdev.com` [H]
- Сопутствующие: `jp/co/sony/vim/framework/core/cloud/ia/soundcomparison/CloudIaSetupSoundComparisonController` (S3-URL сэмплов HRTF/опций, `sound_comparison_format_ver-1.0.json`) [H]

Заголовок `x-api-key` берётся из нативной библиотеки `libiainfo.so` (JNI `IaHttpControllerAndroid.r1eGDEgWpNWwCNLumFu7XMdSp1Ws1iaW`). Значение ключа в отчёт не включено. Авторизация аккаунта (токен пользователя) в этом слое не видна: `z` ставит только `x-api-key`. [H] Возможно, есть отдельная сессия в `account_preference.xml`, не проверялась. [L]

Вызовы авторизованных эндпоинтов мы не выполняли.

## 3. Можно ли забрать и использовать коэффициенты

- Бинарник профиля доступен по `hrtf_url` после получения `hrtf_id`. Для чужого аккаунта без его `hrtf_id` доступа нет. [H]
- Формат бинарника неизвестен: в коде нет парсера, только `byte[]`. Предположение: набор HRIR/HRTF-коэффициентов (SOFA-подобный или собственный), плюс `media_data_key`. [L]
- Публичной спецификации нет. Для обратного инжиниринга нужны скачанные образцы своего профиля (с согласия владельца аккаунта), затем анализ. [M]
- Юридически: профиль создан на основе ушей владельца аккаунта, это персональные биометрические данные. Использовать их только для себя, не распространять. Обход x-api-key и подмена облака не рассматривались.

## 4. Android: custom HRTF для сторонних приложений

- Публичный Spatializer API (Android 12+, `android.media.Spatializer`) даёт только включение эффекта и head-tracking, а не загрузку HRTF. OEM реализует эффект. [M] Источник: https://source.android.com/docs/core/audio/implement-spatial-audio
- Системно (для всех приложений) подставить свой HRTF можно только через OEM/HAL или root. Параметр `360ra_hrtf_personalized` существует только у прошивки Sony/360RA-совместимых устройств. [M]
- Своё приложение может сделать бинауральный рендер: конволюция стерео/многоканального сигнала с HRIR через FFT (например, JNI + libsndfile/ KissFFT, или `AudioTrack` с обработкой PCM). Это работает только внутри Hush, не для Spotify/YouTube. [H, инженерный факт]
- Телефон пользователя (ColorOS, см. memory `hush-app.md`) — не Sony, поэтому `threesixtyra` HRTF-провайдера и `360ra_hrtf_personalized` скорее всего нет. Пакета `jp.co.sony.threesixtyra` на устройстве нет (проверено `pm list packages`). [H]

## 5. MPEG-H 3D Audio

- 360 Reality Audio контент (MPEG-H) декодируется в приложениях 360RA, а не в Hush. [M]
- Fraunhofer опубликовал MPEG-H decoder на GitHub (Fraunhofer-IIS/mpeghdec, лицензия FDK, поддерживается Android) (https://github.com/Fraunhofer-IIS/mpeghdec/wiki/home, https://audioxpress.com/news/fraunhofer-mpeg-h-audio-decoder-software-now-available-on-github). Точные условия коммерческого распространения и патентная лицензия MPEG-H (патентные пулы) не проверены. [M]
- Для Hush: если нужен только декодинг 360RA-потока, это не нужно и сложно юридически. Если нужен спатиал для своих файлов, достаточно конволюции PCM. [M]

## 6. Лицензии и юридические риски

- Sony SDK для персонализации публично не найден, значит доступ к API без договора с Sony не предусмотрен. [M]
- Использование профиля Sony вне их приложений нарушает, вероятно, их ToS (Sony Cloud service ToS, `https://www.sony.net/Products/cloud-service-for-hes/tos/` встречается в ресурсах). [M] Текст ToS не читался.
- Биометрия (фото ушей) — персональные данные, GDPR/152-ФЗ. Не хранить и не передавать другим.
- `x-api-key` из нативной библиотеки — ключ Sony, использовать его в Hush нельзя.

## 7. Реалистичный план (если всё же хочется)

| Этап | Что | Усилие | Риск |
|---|---|---|---|
| A | Бинауральный рендер в Hush с общим HRIR (например, публичный KEMAR/CIPIC) | 1-2 недели | Низкий |
| B | Поддержка пользовательского HRIR-файла (SOFA/WAV импорт) внутри Hush | +1 неделя | Низкий |
| C | Разбор формата профиля (нужны свои образцы, с согласия владельца аккаунта) | 1-3 недели, неопределённо | Средний |
| D | Интеграция с cloud Sony (получение `hrtf_id`, скачивание) | высокий, нужен договор с Sony | Высокий (ToS, ключи) |
| E | Системный HRTF на телефоне | только root + HAL, ColorOS не поддерживает | Высокий |

Рекомендация: этапы A-B. Этап D не делать без договора. Этап E — NO-GO.
